# Porchlight API v1 (CONTRACT)

This is the contract between `services/api` and its clients: the web app, the Apple apps and Flint. The TypeScript shapes in `services/api/src/types/api.ts` must match it exactly. Change both in the same commit.

## Conventions

- **Base URL:** `https://porchlight.xanom.co/v1` in production (domain not final). Local: `http://localhost:8787/v1`.
- **Bodies:** JSON, `content-type: application/json`. Field names are camelCase.
- **Timestamps:** ISO 8601 UTC strings with milliseconds, such as `"2026-11-08T17:04:00.000Z"`. D1 stores milliseconds since epoch, and the API converts. The one exception is a date-only ETA (see "The Package object").
- **Ids:** lowercase UUID strings. Package and device ids are generated by the client.
- **Envelope:** every response, success or error, has this shape:

  ```json
  { "ok": true,  "data": { ... }, "error": null }
  { "ok": false, "data": null, "error": { "code": "not_found", "message": "No such package", "details": { } } }
  ```

  `details` is optional and only appears on some errors (see 409 below).
- **Carrier and status values** come from `@porchlight/carriers`.
  - `carrier`: `usps ups fedex dhl dhl_ecommerce amazon ontrac lasership uniuni jitsu other`
  - `status`: `label_created in_transit out_for_delivery available_for_pickup delivered exception returned unknown`

### Authentication

| Kind | How it is sent | Used by |
|---|---|---|
| Session | `Authorization: Bearer <token>` (native) or the `porchlight_session` cookie (web: HttpOnly, Secure, SameSite=Lax, Path=/v1) | everything marked **session** |
| API token | `Authorization: Bearer plt_<token>` with scope `imports:write` | `POST /v1/imports/flint` only |
| None | | sign-in, `POST /v1/pairing/claim` |

The server stores only SHA-256 hashes of tokens. A request that uses the cookie and changes state (anything but GET) must send an `Origin` that equals `APP_ORIGIN`; if it doesn't, the server answers 403. CORS allows only `APP_ORIGIN`, with credentials.

### Errors

| HTTP | `code` | When |
|---|---|---|
| 400 | `bad_request` | invalid JSON or a field that fails validation; the message names the field |
| 401 | `unauthorized` | credentials missing, invalid or expired |
| 403 | `forbidden` | the API token lacks the scope, or the cookie request has a bad Origin |
| 404 | `not_found` | unknown endpoint, or a resource that doesn't exist or belongs to someone else |
| 405 | `method_not_allowed` | the path exists but not with this method |
| 409 | `conflict` | uniqueness clash; `details` explains (see packages) |
| 429 | `rate_limited` | over a limit; a `Retry-After` header gives the wait in seconds |
| 503 | `unavailable` | a required secret is not configured (for example `RESEND_API_KEY`) |
| 500 | `internal` | anything else; the details are logged on the server, never returned |

### Rate limits (KV token bucket, approximate)

| Bucket | Limit |
|---|---|
| `POST /v1/auth/*` per IP | 10 a minute |
| `POST /v1/auth/email/start` per email | 3 per 15 minutes |
| `POST /v1/auth/email/verify` with code, per email | 5 per 15 minutes |
| `POST /v1/pairing/claim` per IP | 5 per 10 minutes |
| `POST /v1/imports/*` per user | 30 a minute |
| `POST /v1/packages/:id/refresh` per package | 1 per 2 minutes |

## Auth

### POST /v1/auth/apple
Auth: none. Signs in with Apple, creating the account on first use. The identity token is checked against Apple's JWKS, and its `aud` must be one of `APPLE_CLIENT_IDS`.

Request:
```json
{ "identityToken": "eyJ...", "nonce": "raw-nonce", "client": "ios", "deviceId": "6f1c...-uuid" }
```
`client` is `ios`, `macos` or `web`. `deviceId` is optional and links the session to a device.

Response 200:
```json
{ "token": "base64url-32-bytes", "user": { "id": "uuid", "email": "a@b.c", "hasApple": true, "createdAt": "..." }, "created": false }
```
For `client: "web"`, `token` is `null` and the session comes back as a `Set-Cookie`.
Errors: 400, 401 (the token fails verification), 403, 429.

When `client` is `web` and an `Origin` header is present, it must equal `APP_ORIGIN`, or the server answers 403 `forbidden` (login CSRF guard). The same rule applies to `/auth/email/start` and `/auth/email/verify`.

If the Apple account's verified email matches an existing email-only user, the Apple id is linked to that user rather than starting a second account.

### POST /v1/auth/email/start
Auth: none. Sends a magic link through Resend. The response is the same whether or not the email has an account.

Request: `{ "email": "a@b.c", "client": "web" }`
Response 202: `{ "sent": true }`
The link is `https://<APP_ORIGIN host>/auth/verify?token=<token>`. Native apps get it as a universal link. The token is single-use and expires after 15 minutes.
The email also contains a 6-digit code, valid for the same 15 minutes. Using either the link or the code spends both.
Errors: 400, 403, 429, 503 (no `RESEND_API_KEY`).
Local dev: with no `RESEND_API_KEY`, `EMAIL_DEV_LOG=1` and an `APP_ORIGIN` on `localhost` or `127.0.0.1`, the server writes the link and code to the Worker log instead of sending mail and answers 202. Any other origin ignores the var.

### POST /v1/auth/email/verify
Auth: none. Trades the link token, or the email and 6-digit code, for a session, creating the user if the email is new.

Request, either:
- `{ "token": "...", "client": "ios", "deviceId": "uuid" }`
- `{ "email": "a@b.c", "code": "123456", "client": "ios", "deviceId": "uuid" }`

`deviceId` is optional.
Response 200: same as `/auth/apple`.
Errors: 400, 401 (the token or code is unknown, used or expired), 403, 429.

### POST /v1/auth/signout
Auth: session. Deletes the current session and, if one is linked, its device row (and with it the APNs token).
Response 200: `{ "signedOut": true }`. Web also gets a `Set-Cookie` that clears the cookie.

### GET /v1/me
Auth: session.
Response 200: `{ "user": { "id": "uuid", "email": "a@b.c" | null, "hasApple": true, "createdAt": "..." } }`

### DELETE /v1/me
Auth: session. Deletes the user and every row that belongs to them, right away (SPEC §9). Nothing is kept as a tombstone.
Response 200: `{ "deleted": true }`. Web also gets a `Set-Cookie` that clears the cookie.

## Devices

### PUT /v1/devices/:id
Auth: session. Registers or updates this device and links the current session to it. The call is idempotent.

Request:
```json
{ "platform": "ios", "apnsToken": "hex", "appVersion": "1.0 (12)", "environment": "sandbox" }
```
- `apnsToken` and `appVersion` may be `null`.
- `environment` is `sandbox` or `production` and names the APNs host the token belongs to. Development builds (the `aps-environment` entitlement is `development`) send `sandbox`; TestFlight and App Store builds send `production`. A token only works on its own host. When `environment` is left out, a new device gets `production` and an existing one keeps what it had.

Response 200, the `Device`:
```json
{ "id": "uuid", "platform": "ios", "apnsToken": "hex", "appVersion": "1.0 (12)", "environment": "sandbox" }
```
Errors: 400, 404 (the id belongs to another user).

Pushes go to `api.sandbox.push.apple.com` for `sandbox` devices, and to the `APNS_HOST` var (default `api.push.apple.com`) for `production` devices. The `apns-topic` is `APNS_TOPIC`, `co.xanom.porchlight`, on both iOS and macOS.

## Sessions

### GET /v1/sessions
Auth: session. Lists the user's signed-in sessions, most recently seen first.

Response 200:
```json
{ "sessions": [ {
  "id": "uuid", "platform": "ios", "appVersion": "1.0 (12)",
  "createdAt": "2026-11-01T10:00:00.000Z", "lastSeenAt": "2026-11-08T17:04:00.000Z", "current": false
} ] }
```
- `platform` is the linked device's platform, or else the `client` the session signed in with (`ios`, `macos`, `web`). It is `null` only for sessions created before the server recorded it.
- `appVersion` comes from the linked device and is `null` without one (web).
- `lastSeenAt` is updated at most once a minute.
- `current` is true for the session that made the request.

### DELETE /v1/sessions/:id
Auth: session. Signs that session out, and deletes its device row (and with it the APNs token) unless another of the user's sessions still uses that device. Deleting the current session is the same as signing out.
Response 200: `{ "deleted": true, "signedOut": false }`. `signedOut` is true when the deleted session was the caller's own; a web caller then also gets a `Set-Cookie` that clears the cookie.
Errors: 400 (not a UUID), 404 (unknown, or another user's session).

## Sync

### GET /v1/sync?since=&lt;cursor&gt;
Auth: session.

- Without `since`, the server sends a full snapshot of every live package (archived ones included) with their events, and `deleted` is empty.
- With `since`, it sends every package whose `updated_at` is later than the cursor. Packages that were deleted come back only as ids in `deleted`.
- Pages hold up to 200 packages. While `hasMore` is true, call again straight away with the returned `cursor`.
- `events` holds every event of each returned package, so clients replace a package's events wholesale. A package's `updatedAt` changes whenever it gains an event.
- The cursor is opaque: today it encodes `(updated_at, id)`. An unknown or malformed cursor returns 400, and the client should then do a full sync.

Response 200:
```json
{
  "packages": [ {
    "id": "uuid", "carrier": "ups", "trackingNumber": "1Z...", "title": "Headphones", "merchant": "Best Buy",
    "orderId": null, "source": "flint", "status": "in_transit", "statusDetail": "Departed facility",
    "etaStart": "2026-11-10", "etaEnd": "2026-11-10", "etaDateOnly": true, "deliveredAt": null,
    "lastCheckedAt": "2026-11-08T17:00:00.000Z", "archivedAt": null, "updatedAt": "2026-11-08T17:00:01.000Z",
    "items": [ { "name": "Headphones", "imageUrl": null, "quantity": 1 } ]
  } ],
  "events": [ {
    "id": "uuid", "packageId": "uuid", "occurredAt": "2026-11-08T09:12:00.000Z", "status": "in_transit",
    "description": "Departed FedEx location", "location": "Oakland, CA, US"
  } ],
  "deleted": ["uuid"],
  "cursor": "opaque",
  "hasMore": false
}
```

## Packages

### The Package object

Every endpoint that returns a package (sync, `GET`/`PUT /v1/packages/:id`) uses this shape:

```json
{
  "id": "uuid", "carrier": "ups", "trackingNumber": "1Z999AA10123456784", "title": "Headphones", "merchant": "Best Buy",
  "orderId": null, "source": "manual", "status": "in_transit", "statusDetail": "Departed facility",
  "etaStart": "2026-11-10", "etaEnd": "2026-11-11", "etaDateOnly": true,
  "deliveredAt": null, "lastCheckedAt": "2026-11-08T17:00:00.000Z", "archivedAt": null,
  "updatedAt": "2026-11-08T17:00:01.000Z",
  "items": [ { "name": "Headphones", "imageUrl": null, "quantity": 1 } ]
}
```

**ETA.** `etaStart` and `etaEnd` are only what the carrier said; the server never computes one. Their form depends on `etaDateOnly`:
- `true`: both are calendar dates, `"YYYY-MM-DD"`. The date is the carrier's local delivery date. Clients show it as that date in every time zone and never convert it to an instant.
- `false`: both are ISO 8601 UTC instants, such as `"2026-11-10T22:00:00.000Z"`, shown in the viewer's time zone.
- With no ETA, both are `null` and `etaDateOnly` is `false`. A one-sided ETA from the carrier comes back as a single point (`etaStart` = `etaEnd`).

A carrier time with no UTC offset (UPS delivery windows, for example) names no instant, so the server keeps only its date and sends the ETA as date-only.

`title`, `merchant`, `orderId` and `archived` belong to the client. Status, ETA, events, `lastCheckedAt` and `deliveredAt` belong to the server: the client can't write them, and the server ignores them if sent. When two writes touch the same field, the one the server receives last wins (SPEC §3). Fields left out of a PUT are not changed.

### GET /v1/packages/:id
Auth: session. One live package with its items and events, for deep links (a push or a Flint chip that names a `packageId`). Native apps can use it to fetch a package that has not synced yet.

Response 200:
```json
{
  "package": { "id": "uuid", "...": "the Package object" },
  "events": [ { "id": "uuid", "packageId": "uuid", "occurredAt": "2026-11-08T09:12:00.000Z", "status": "in_transit",
                "description": "Departed FedEx location", "location": "Oakland, CA, US" } ]
}
```
`events` is newest first, the same rows sync sends for the package.
Errors: 400 (not a UUID), 404 (unknown, deleted, or another user's package).

### PUT /v1/packages/:id
Auth: session. Creates the package or updates it. The call is idempotent.

Request (every field is optional on update; `trackingNumber` is required on create):
```json
{ "trackingNumber": "1Z999AA10123456784", "carrier": "ups", "title": "Headphones", "merchant": null,
  "orderId": null, "source": "manual", "archived": false }
```
- The server normalizes `trackingNumber` with `normalizeNumber`.
- When `carrier` is left out on create, the server takes the top `detectCarrier` candidate, or `other` if there is none.
- `source` applies only on create. It accepts `manual` or `share`; `amazon` and `flint` are set by the import endpoints.
- `archived: true` sets `archivedAt` and `false` clears it.
- On create, the package is queued for its first check right away.

Response: 201 on create, 200 on update, with the `Package` as data.
Errors:
- 400
- 404: the id belongs to another user
- 409 `conflict` with `details`:
  - `{ "reason": "duplicate", "existingId": "uuid" }` when the user already has this `(carrier, trackingNumber)`. The client should adopt `existingId` and drop its own id.
  - `{ "reason": "deleted" }` when the id was deleted. Ids are never reused.

### DELETE /v1/packages/:id
Auth: session. Leaves a tombstone: `deleted_at` is set and the items and events are removed. Deleting a package that is already deleted returns the same response.
The tombstone's `tracking_number` gets the suffix `~deleted~<id>`, so the same number can be tracked again under a new id. Server lookups by number filter on `deleted_at IS NULL`.
Response 200: `{ "id": "uuid", "deletedAt": "..." }`
Errors: 404.

### POST /v1/packages/:id/refresh
Auth: session. Queues an immediate carrier check with reason `manual`. Allowed once every 2 minutes per package.
Response 202: `{ "queued": true, "nextAllowedAt": "..." }`
Errors: 404, 429 with `Retry-After`.

## Imports

Each item is deduped by `(user, source, dedupeKey)`. Importing a key again never creates a second package, but it does update the fields the source owns. Items are processed one at a time, and a bad item is reported as `rejected` without failing the rest. A request carries 1 to 100 items.

Response 200 for both endpoints:
```json
{ "results": [ { "dedupeKey": "<key>", "packageId": "uuid", "outcome": "created" } ] }
```
`outcome` is one of:
- `created`
- `updated`
- `unchanged`
- `rejected`, which adds `"reason": "..."` and has `packageId: null`

When an imported `(carrier, trackingNumber)` already exists as a package, the import attaches to that package (outcome `updated` or `unchanged`).

### POST /v1/imports/flint
Auth: session, or an API token with `imports:write`. Flint sends only the fields below and never mail bodies (SPEC §7).

Request:
```json
{ "items": [ {
  "trackingNumber": "9400...", "carrier": "usps", "merchant": "Etsy", "subject": "Your order has shipped",
  "messageDate": "2026-11-08T15:00:00.000Z", "dedupeKey": "<CAF...@mail.example.com>"
} ] }
```
- `carrier` is optional. When it is missing, the server detects it.
- On create, the package gets `title` = `subject` and `merchant` = `merchant`, with `source: "flint"`.
- Re-imports never overwrite a title the user edited.

### POST /v1/imports/amazon
Auth: session only (the native apps).

Request:
```json
{ "items": [ {
  "orderId": "112-1234567-1234567", "shipmentId": "Dxyz", "carrier": "amazon", "trackingNumber": "TBA123456789012",
  "title": "USB-C cable", "items": [ { "name": "USB-C cable", "imageUrl": "https://m.media-amazon.com/...", "quantity": 2 } ],
  "etaStart": "2026-11-09", "etaEnd": "2026-11-09", "etaDateOnly": true,
  "observed": {
    "status": "out_for_delivery", "statusDetail": "Out for delivery", "observedAt": "2026-11-09T14:00:00.000Z",
    "deliveredAt": null,
    "events": [ { "occurredAt": "2026-11-09T13:05:00.000Z", "status": "out_for_delivery",
                  "description": "Out for delivery", "location": "San Jose, CA" } ]
  }
} ] }
```
- The server builds `dedupeKey` as `"<orderId>:<shipmentId>"`, and that is the key the results echo back. When Amazon splits one shipment into several packages, the app sends `shipmentId` as `"<shipmentId>-<n>"` for the n-th package after the first.
- The import sets `source: "amazon"`, `orderId`, the items (each import replaces them all), and the ETA Amazon showed.
- `etaDateOnly` is optional and follows the Package rule: `true` means `etaStart`/`etaEnd` are `"YYYY-MM-DD"` (Amazon showed a day, such as "Arriving Monday"); left out or `false` means they are ISO 8601 date-times with an offset (Amazon showed a time window). An ETA that doesn't match the flag rejects the item. Both `null` keeps the stored ETA.
- `observed` is optional and is sent for Amazon Logistics (TBA) packages. When `observedAt` is newer than the package's last check, the server applies its `status`, `statusDetail` and `deliveredAt`, adds its events (deduped by `raw_hash`) and sets `lastCheckedAt = observedAt`.
- The aggregator is never asked about TBA numbers (docs/research/aggregators.md).

## Integrations

### GET /v1/integrations/amazon
Auth: session. How the last Amazon import went, as the native app that ran it reported (SPEC §6, "Failure is visible"). The web shows it in Settings. The server stores no Amazon data: only the state, two times and one sentence of error text.

Response 200:
```json
{ "amazon": {
  "state": "needs_sign_in", "lastImportAt": "2026-11-08T17:00:00.000Z",
  "lastError": "Amazon asked you to sign in again.", "reportedAt": "2026-11-08T17:30:02.000Z", "platform": "macos"
} }
```
- `amazon` is `null` until a device reports, and after `DELETE`.
- `state` is `ok`, `needs_sign_in` (Amazon wants a new sign-in or a captcha on the device) or `parse_failed` (the pages loaded but the parser found nothing it knows).
- `lastImportAt` is the last import that worked, or `null`.
- `lastError` is `null` when `state` is `ok`.
- `reportedAt` is when the server got the report. `platform` is the reporting session's device platform, else its sign-in `client`.
- One row per account: when several devices import, the latest report wins.

### PUT /v1/integrations/amazon
Auth: session. A native app sends this after each import that ends in one of the three states. A network failure is not reported.

Request: `{ "state": "ok", "lastImportAt": "2026-11-08T17:00:00.000Z", "lastError": null }`
- `state` and `lastImportAt` (nullable) are required. `lastError` is optional, up to 300 characters, and is dropped when `state` is `ok`.

Response 200: the same body as `GET`.
Errors: 400.

### DELETE /v1/integrations/amazon
Auth: session. Clears the status. The app calls it on Disconnect.
Response 200: `{ "deleted": true }`

## Pairing and API tokens

### POST /v1/pairing/start
Auth: session. Returns a one-time code for Flint to claim. The code is 8 Crockford base32 characters shown as `ABCD-EFGH`, and it expires after 10 minutes. Starting a new pairing does not cancel earlier codes.
Response 201: `{ "code": "ABCD-EFGH", "expiresAt": "..." }`

### POST /v1/pairing/claim
Auth: none (the code is the credential). The claim is case-insensitive and ignores the dash. A code works once, and only 5 attempts are allowed per code.

Request: `{ "code": "ABCD-EFGH", "label": "Flint on Neel's MacBook Pro" }`
Response 201: `{ "token": "plt_...", "tokenId": "uuid", "scopes": ["imports:write"] }`
The token is shown once.
Errors: 400, 401 (the code is unknown, used or expired), 429.

### GET /v1/tokens
Auth: session.
Response 200: `{ "tokens": [ { "id": "uuid", "label": "Flint on ...", "scopes": ["imports:write"], "createdAt": "...", "lastUsedAt": "..." | null } ] }`

### DELETE /v1/tokens/:id
Auth: session. Revokes the token, which stops working at once.
Response 200: `{ "deleted": true }`
Errors: 404.

## Not in v1 / server-internal

- The aggregator webhook endpoint (`POST /v1/hooks/aggregator`) is added when the aggregator account exists. It authenticates with the aggregator's shared secret and is not a client API.
- Push payloads: APNs `aps.alert` is sent for `out_for_delivery`, `delivered` and `exception`. Every other change sends `content-available: 1` with `{ "packageId": "uuid" }`.
